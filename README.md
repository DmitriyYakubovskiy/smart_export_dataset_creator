# Анамнез — создание датасета

Приложение для ручного сбора анамнезов из Word, заполнения типизированных колонок и разметки упоминаний в тексте. Один аккаунт без регистрации. FastAPI, SQLite, браузер. Лицензия [MIT](LICENSE).

## Быстрый запуск

Требуются Docker Compose v2 и Python 3 для генерации настроек:

```bash
git clone https://github.com/DmitriyYakubovskiy/smart_export_dataset_creator.git
cd smart_export_dataset_creator
python3 setup.py
docker compose up -d --build
```

Если используете ZIP с обновлением, распакуйте каталог smart_export_dataset_creator и выполняйте последние две команды из него. setup.py создаёт .env и показывает логин и случайный пароль. Существующий .env он сохраняет. Пароль можно изменить в .env (не менее 12 символов); затем пересоздать контейнер через `docker compose up -d --force-recreate`. Старые сессии после смены пароля перестанут работать.

По умолчанию сервер слушает 127.0.0.1:8080. Для доступа со своего компьютера:

```bash
ssh -L 8080:127.0.0.1:8080 user@SERVER_IP
```

Откройте http://localhost:8080. Для закрытой локальной сети задайте BIND_ADDRESS=0.0.0.0 в .env и пересоздайте контейнер: адрес будет http://SERVER_IP:8080. Для доступа через интернет настройте HTTPS на reverse proxy и COOKIE_SECURE=true; обычный HTTP требует COOKIE_SECURE=false.

## Этап 1. Word → анамнезы и значения колонок

1. Загрузите один или несколько .docx, каждый до 30 МБ.
2. В списке видны файлы и их статусы: «Новый», «В процессе», «Готово». Есть поиск и фильтр статусов.
3. Откройте новый Word — он автоматически станет «В процессе». Готовый документ при обычном открытии остаётся готовым.
4. Справа доступен просмотр текста и таблиц. Кнопка поиска последовательно показывает вхождения «анамнез». Точная вёрстка Word доступна через скачивание оригинала.
5. Выделите анамнез в документе и нажмите «Взять выделенное» или вставьте текст из Word. Дайте название и заполните колонки прямо в форме, например «Курение: не курит». Нажмите «Сохранить анамнез».
6. Повторите для всех анамнезов данного документа. Источник связывается автоматически: histories.document_id → documents.id. Повторно загруженные файлы даже с одинаковым именем имеют разные ID.
7. Когда документ полностью разобран, поменяйте его статус на «Готово». У всех сохранённых анамнезов должны быть заполнены все активные колонки. False и 0 считаются заполненными значениями, null/пустое поле — нет. Документ без анамнезов можно вручную завершить после проверки.

Анамнез разрешено сохранять с незаполненными колонками как черновик, но завершение документа будет заблокировано до их заполнения. Изменение текста или значений колонок, добавление/удаление анамнеза возвращает исходный документ в работу. Черновик формы хранится только в открытой вкладке до нажатия «Сохранить».

## Колонки и типы данных

«Колонки и типы данных» доступны в обоих разделах. При добавлении укажите стабильный код, название, цвет и тип:

| Тип | Допустимые значения |
|---|---|
| int | Целое число в диапазоне ±(2^53−1), включая 0 |
| bool | Да / Нет; в JSON настоящие true / false |
| enum | Выпадающий список, варианты задаются по одному на строку |

Начальная колонка создаётся из app/seed_labels.json:

```json
{
  "code": "SMOKING_MENTION",
  "name": "Курение",
  "data_type": "enum",
  "options": ["курит", "не курит", "бросил", "неизвестно"]
}
```

Это начальные данные. Обработчики, формы и проверка типов универсальны: курение не зашито в логику. Через интерфейс можно добавить, например, ALCOHOL_MENTION (список), SMOKING_YEARS (int), PASSIVE_SMOKING (bool). Код и тип после создания неизменяемы; для другой схемы создайте новую колонку. Метку можно отключить/включить; её прежние значения и фрагменты сохраняются.

**Добавление любой колонки автоматически возвращает все готовые документы и все готовые анамнезы в «В процессе».** Включение/отключение колонки также сбрасывает готовность. Тексты, заполненные значения и фрагменты при этом не удаляются. Новая колонка появляется пустой; её нужно заполнить и повторно проверить записи. Схема имеет номер revision: завершение из вкладки с устаревшей схемой отклоняется с HTTP 409.

Инициализация при перезапуске не дублирует колонки и не сбрасывает статусы без изменений схемы. Новые колонки, добавленные в seed JSON и отсутствующие в базе, создаются при следующем запуске с тем же сбросом готовности. Изменение старого объекта в seed не перезаписывает пользовательский справочник.

## Этап 2. Анамнез → фрагменты и результаты

Откройте «Разметка» или нажмите «Разметить» на карточке анамнеза.

1. Выберите анамнез. Новая запись автоматически переходит в «В процессе».
2. Выделите слова мышью непосредственно в тексте анамнеза.
3. Выберите колонку/метку и результат фрагмента. Для курения это «курит», «не курит», «бросил», «неизвестно».
4. Нажмите «Назначить метку». Сохраняются ID анамнеза, ID колонки, начало, конец, точный текст, результат. ID документа получается через связь с анамнезом и явно присутствует в API/экспорте.
5. Можно разметить несколько одинаковых фраз в разных местах и пересекающиеся фрагменты. Один диапазон с одной колонкой не дублируется. У сохранённого фрагмента можно поменять результат или удалить фрагмент.
6. Нажмите «Разметка завершена». Анамнез станет готовым и перейдёт в список размеченных. Все активные колонки на первом этапе должны быть заполнены; у каждого существующего фрагмента должен быть корректный результат. Если упоминаний нет, завершайте без фрагментов, например с общим значением «неизвестно».

Готовность Word означает завершение извлечения анамнезов и заполнения колонок. Готовность анамнеза означает завершение текстовой разметки. Это два независимых этапа: документ может быть готов, а выделения в его анамнезах ещё не готовы. Изменение выделений/результатов возвращает в работу анамнез, а не первый этап Word.

Общее значение колонки и результат каждого фрагмента хранятся отдельно. Например, анамнез может содержать «раньше курил, сейчас не курит»: у двух упоминаний будут разные результаты, а общее значение у анамнеза выбирает человек. Приложение не определяет статус курения автоматически и не выводит общий результат из отдельных фрагментов.

## Связи и экспорт

```text
Документ (id)
  → Анамнез (id, document_id, текст, значения колонок, статус)
    → Фрагмент (id, history_id, label_id, start, end, text, result)
```

Пример фрагмента для текста «Не курит.»:

```json
{
  "history_id": "id-анамнеза",
  "document_id": "id-документа",
  "document_name": "история.docx",
  "label": "SMOKING_MENTION",
  "start": 0,
  "end": 8,
  "text": "Не курит",
  "result": "не курит"
}
```

Позиции от нуля относительно сохранённого текста анамнеза; end не включается. Единица — Unicode code point, как в Python. Проверяется инвариант `history_text[start:end] == annotation.text`, включая кириллицу и эмодзи. Версия текста проверяется по SHA-256. Текст с существующими фрагментами нельзя менять до удаления его разметки; название и значения колонок менять можно, но изменение значений сбрасывает готовность.

JSON/CSV экспортируют записи со связью на источник, статусы документа и анамнеза, значения колонок с их типами, массив фрагментов и результаты. У фрагмента явно есть history_id и document_id. У анамнеза — id и document_id. `/api/export/json?status=completed` выгружает только анамнезы с завершённой текстовой разметкой. Без фильтра выгружается весь набор. Пустой массив фрагментов у готового анамнеза — проверенный пример без упоминаний.

CSV: UTF-8 BOM, разделитель «;», columns и annotations записаны JSON внутри ячеек. Формулоподобные пользовательские строки экранируются апострофом для Excel. JSON сохраняет исходный текст. Экспорт использует согласованный снимок SQLite.

## Данные и обновление

В ./data/app.sqlite3 хранятся документы, анамнезы, колонки, значения и разметка. В ./data/files — оригиналы Word и HTML-представления. .env — данные единственного аккаунта. Эти файлы не входят в публичный репозиторий. Сессия действует 12 часов; после 10 неудачных входов с адреса действует ограничение на 10 минут.

Перед обновлением остановите приложение и скопируйте всю папку data вместе с .env:

```bash
docker compose stop
# Скопируйте data и .env в защищённое место
# Обновите исходные файлы из нового архива или git pull --ff-only
docker compose up -d --build
```

Не заменяйте свою data и .env. Таблицы и новые поля SQLite создаются автоматически. Старые документы, анамнезы, метки и выделения сохраняются. У прежних фрагментов result=null: его необходимо заполнить через «Изменить результат». После перехода со старой нетипизированной разметки готовность сбрасывается, поскольку требуются значения новых типов. Для старых пользовательских меток без настроенного типа используется enum с вариантом «упоминание»; для другого набора создайте новую колонку и отключите старую.

Таблицы: documents, histories, labels, history_values, annotations, annotation_reviews, dataset_meta. Удаление анамнеза каскадно удаляет его значения, фрагменты и отметку завершения.

## Проверки

```bash
python -m pip install -r requirements.txt pytest httpx
python -m pytest -q
node tests/test_span_utils.cjs
```

Тесты используют временную базу. Проверяются исходная работа с DOCX, доступ, типы значений, статусы двух этапов, сброс готовности после новой колонки, защита от устаревшей схемы, миграция, источники, результаты фрагментов, точные позиции, экспорт. Результат — TEST_RESULTS.txt. Node.js нужен только для отдельной проверки JS-логики Unicode и пересекающихся фрагментов, не для работы сервера.

## Ограничения

Только DOCX, не DOC/PDF. Просмотр показывает текст и таблицы, но не точную вёрстку, картинки и колонтитулы Word. Выбор анамнезов, итоговых колонок и результатов делает человек. Нет автоматической классификации, многопользовательских ролей и истории версий. При одновременной правке значения колонки в разных вкладках сохраняется последнее; завершение проверяет текущие обязательные значения и версию схемы. Текстовая разметка защищена проверкой версии текста.

MIT относится к исходному коду и не распространяется на загруженные медицинские документы и пользовательский датасет.
